> 适用：多配色 × 多语言（十几本以上）、需要人工审校、需要按词增量修订的整套卡片交付。
> 单本或少量文件直接走 SKILL.md 的路线 C；本文件是它的工程化放大版。
>

## 1. 核心架构：决策文件是唯一真相源

大批量任务必须把「翻译内容 / 版式决策」和「排版执行」解耦成两层，否则任何小改动都得全量重跑：

```
每本书的决策 JSON（逐条 译文+字号+位置+mode）  ← 唯一真相源
        │  出表
        ▼
翻译台账 xlsx（人看的视图 / 可编辑界面）        ← 不是真相源
        │  回灌（只写回有变化的条目）
        ▼
决策 JSON  ──指纹比对──▶  只重建受影响的那几本 .ai + .pdf
```

两条铁律：

- **排版脚本只读决策 JSON，绝不读 xlsx**。因此改台账的列结构、加注释列、调整列顺序，都不会进入出图链路，不需要重跑成品——除非回灌真的改写了决策文件。
- **台账只是视图**：想改内容必须「在表里改 → 回灌 → 重建」。只改表不回灌，指纹判定为「没变」，重建会直接跳过。

### 本技能提供什么 vs 需要按项目现搭什么

**大批量任务必须先用 `pipeline/` 下的配置驱动脚本，不要直接生成结果。** 这套脚本把出表→回灌→重建→校验闭环做成了可执行工具，零项目绑定：

- **`pipeline/`（决策驱动全套，大批量首选）**：从 `config.example.json` 复制出 `pipeline.json`，声明语言表/配色表/命名模板/决策字段后，直接跑：
  - `ledger_export.py` 出表（出表前自动回灌防丢编辑）
  - `ledger_import.py` 回灌（表头名定位列、`\r↔\n` 归一化、幂等、备份）
  - `letters_export.py` 字母对应表
  - `rebuild.py` 指纹增量重建（单本/单语言/全部/`--force`）
  - `make_jsx.py` 决策驱动生成纯 ASCII JSX
  - `verify.py` 校验（页数 + `text=0` + 齐全）
  - `common.py` 共享层；详见 `pipeline/README.md`。
- **`scripts/run_batch.ps1`**：Illustrator 单会话批处理骨架（`-List / -MaxRetry / -WaitMs / -DoneMarker`），由 `rebuild.py` 调用。JSX 侧约定：自身同目录写 `<名>.log`，成功含完成标记、失败含 `ERROR:`。
- **`scripts/make_translation_xlsx.py`**：轻量台账（一个对象一行、一种语言一列），适合**中小批量、无审校回灌需求**。大批量工程化交付用 `pipeline/` 决策驱动台账，两者不是同一套。
- **需按项目现搭**：决策**引擎**（字体实测字宽 → 避让/折行/短译法 → 写决策 JSON）和复杂几何（标题椭圆、插图墨迹 bbox）强依赖具体源稿，`pipeline/` 不含这部分——它消费决策 JSON、不生产决策 JSON。按第 4 / 10 节方法论与 `pipeline/config.example.json` 现搭；决策 JSON 契约见 `pipeline/README.md`。

译文来源：大批量卡片通常用**人工整理的固定词条表**（英文原词 → 各语言译文，几百条），而不是运行时调用翻译模型。复合词/缩写、放不下时的短同义词、字号微调各用一张补充映射表。决策引擎按字体实测字宽、画板边框、插图位置给每个词定 `keep / single / short / wrap / shift2 / manual`，写进决策 JSON，执行脚本照表替换。

## 2. 目录与命名

```
输出根/
├── xlsx/                     台账固定放这里，不带日期，永远最新
│   ├── <项目>_翻译总表.xlsx
│   └── <项目>_字母对应表.xlsx
└── <日期或批次>/             成品按批次分目录
    ├── ai/                   可编辑 .ai（保留 PDF 兼容层）
    └── pdf/                  已转曲 .pdf
```

- 台账不进日期目录，改完覆盖，始终是当前最新一版。交付时发 `xlsx/` + `<日期>/` 两块。
- **序号贯穿全流程**：源稿文件名 → 成品文件名 → 台账「序号」列是同一个数字，直接对应配色/版本，便于核对。
- 成品名保留源稿的序号，不擅自重命名；需要去序号时用一个显式开关控制。

## 3. 闭环四阶段：出表 → 审校 → 回灌 → 重建

| 阶段 | 要点 |
|---|---|
| 出表 | 从决策 JSON 生成台账。**出表前若目标已存在，先自动回灌一遍再覆盖**，防止用户在表里的编辑被覆盖丢失（提供 `NO_SYNC` 开关跳过）。 |
| 审校 | 人只改标色（浅黄底）的可编辑列；主键列、只读列不动。 |
| 回灌 | 只写回有变化的条目；写前备份；幂等（无改动 `changed=0`）。提供 `--dry` 先看差异。 |
| 重建 | 指纹比对后只重跑受影响的书；`all` 模式自动跳过未变的。 |

用 `pipeline/` 脚本对应四阶段：`python pipeline/ledger_export.py`（出表）→ 人工审校 → `python pipeline/ledger_import.py [--dry]`（回灌）→ `python pipeline/rebuild.py all`（重建）→ `python pipeline/verify.py`（校验）。命令行与配置见 `pipeline/README.md`。

**回灌的两个必踩坑**：

- **按表头名定位列，不要写死列号**。加列、调列顺序后仍要能正确回灌；主键用稳定的 ID，不用行号。
- **换行符归一化**：xlsx 会把软回车 `\r` 存成 `\n`。写入前做双向 `\r ↔ \n` 归一化，否则会误判成「全表都改了」，把排版覆盖掉。

## 4. 翻译台账的设计要点

- **拆分视图**：
  - 按语言的 sheet：每条一行，含 ID / 序号 / 配色 / 画板 / 页码 / 字体 / 字号 / 中文注释 / 英文原文 / 译文 / 模式 / 审校备注。
  - 全语言对照 sheet：一个英文词条一行，各语言横排，用于横向比较选词是否一致、发现缺漏。
  - 总览 sheet：统计 + 用法说明。
- **只读列 vs 可编辑列**：字体、英文原文、ID、序号、配色、画板、页码、**字号**设为只读（灰底）；译文、中文注释设为可编辑（浅黄底）。这样用户不会误改定位信息，也改不到字号。
- **字号**：取源稿同画板同位置的实测字号（从 PDF span 按「配色, 页码=画板+1, 词」取），只供人看。**正文一律不许缩**（只有标题能改大小，标题字号由椭圆适配算），所以回灌不再写 `sz`；旧版"改小字号救长词"的做法已撤销——长词靠换词/折行/让位。
- **页码 = 画板 + 1**：画板是 0-based 索引，页码从 1 开始，等于 PDF 页序。标题行无页码。
- **中文列：是注释还是译文，取决于目标语言**。
  - 目标语言是**外语**（如意/葡/俄/德/法）时：中文只是**注释**，帮审校判断原词含义，**不参与排版**。数据放独立 gloss JSON：`words` 通用释义 + `overrides` 按「配色|画板|词」的精确覆盖（同一个词在不同页含义不同时用，如颜色页的 orange vs 水果页的 orange）。注释列可改，回灌写回 gloss JSON。
  - 目标语言**包含中文**时：中文就是**译文本身，必须参与排版**，走「译文」列（回灌写进决策 JSON，进出图链路）。此时中文不再是可有可无的注释——字形覆盖预检、CJK 字体回退（如微软雅黑 Bold / 思源黑体）、按字体实测字宽做溢出收缩、基线/墨迹居中都要按中文处理，详见 SKILL.md 的 CJK 与溢出规则。不要因为台账里有「中文注释」列就误判中文任务不用排版。
- **字母认知卡特例**：译文首字母可能不再与 A–Z 对应（A=apple→A=mela）。不要重绘字母/插图——保留源稿英文 A–Z 与插图，只翻译单词，另出一张《字母对应表》说明即可。

## 5. 指纹增量重建

- **签名 = 该本决策文件的 (大小, mtime) + `width_tables.json` 的 (大小, mtime) + 源稿的 (大小, mtime)**。
- **`width_tables.json` 必须计入**：折行、短译、每槽最大宽度都在这个文件里，它不是脚本而是决策数据。漏掉它就会出现最迷惑的「规则不执行」——改完折行规则直接 `rebuild.py all`，全部 `SKIP (unchanged)`，成品当然没变。
- **故意不把生成脚本计入签名**：改脚本模板不应悄悄让全部书失效；要强制全量重做时用显式的 `--force`。
- 签名未变且成品齐全 → 整本 `SKIP (unchanged)`，无改动时 `all` 模式 0 秒完成。
- 重建后回写签名到 manifest。
- 选择器设计：`rebuild.py <lang> <color>` 单本 / `<lang>` 该语言全部 / 逗号分隔多本 / `all` 全部跳过未变 / `all --force` 强制全量。

## 6. Illustrator 单会话稳定性（关键坑）

**崩溃根因**：关闭一个文档后到打开下一个大文件之间的等待太短。Illustrator 关闭文档后需要时间完成内部清理，等待不足会触发 `RPC_E_SERVERFAULT (0x80010105)`，进程死掉、后续级联失败。

- **不是**内存累积到极限，**也不是**重复打开已打开的文件。诊断可在生成脚本时加开关，记录 `docs_before_open / docs_after_close`，确认每本都关干净即可排除。
- **实测**：等待 0.2s → 第 4 本崩；1s / 3s → 全过；取 **2 秒**为正式值。单会话连跑 24 本 24/24 零崩溃。
- **不要按「每 N 本」分段重启**：等待充足后，分段重启只是白白多付启动时间。一个 `run_batch.ps1 -List <list>` 调起一个 Illustrator 顺序跑完全部。
- **失败重试**：每本失败自动重试 2 次；重试前删旧日志，用日志里的完成标记判定成功（不要信 COM 返回值，常为 undefined）。
- **不要强杀 Illustrator 进程**：强杀后 COM 失效，报 `0x800706BA`，必须清进程后重跑失败本。中途不要碰 Illustrator 窗口。
- **保留 PDF 兼容层**：`IllustratorSaveOptions.pdfCompatible = true`。关掉能省几秒/本、体积减半，但 .ai 只能用 Illustrator 打开；客户常靠兼容层用 Acrobat 预览或置入排版软件。仅在试验时提供关闭开关。
- **前置检查**：关闭被占用的 PDF 阅读器（被锁的 PDF 会让 Illustrator **静默保存失败**）、清残留 Illustrator 进程、确认磁盘空间、关掉 Excel 里的台账。

PowerShell 批处理骨架：直接用 `scripts/run_batch.ps1`（`powershell -NoProfile -ExecutionPolicy Bypass -File run_batch.ps1 -List books.txt`）。它已内建：干净启动（清残留进程并等退出）→ 建 COM 对象（带 3 次重试）→ 顺序 `DoJavaScriptFile` 每本后 `Start-Sleep -Milliseconds 2000`（`-WaitMs` 可调）→ 按日志完成标记判定（`-DoneMarker` 可配）→ 失败重试 → `Quit()` 优雅退出（最多等 90 秒再强制结束）。

## 7. 提速机制

| 机制 | 效果 |
|---|---|
| 几何坐标缓存（如标题椭圆位置）以**源稿 size/mtime 为键** | 首次遍历上万路径找锚点（几秒），之后直接读缓存降到 0 ms；源稿一改自动失效重采。 |
| 未改动跳过（manifest 指纹） | 无改动时 `all` 模式 0 秒完成。 |
| 少做属性调用 | 只解锁必要的图层/文本框，不遍历两万个页面对象。 |

时间预算经验：耗时大头是两次 `saveAs`（存 AI + 存 PDF），尤其大插图源稿；打开文档只占很小比例。因此**优化重点在保存环节，不是打开环节**；把「同一文档连续翻译多语言以省打开时间」的想法收益极小且破坏正确性（见第 10 节）。

## 8. 校验

- 页数与源稿一致；`get_text()` 为空（全部转曲）；文件名带序号。
- 抽查：标题在容器内、正文不越界、插图不被文字压住、字母页单词与字母对应表一致。
- 渲染缩略图拼版目检；必要时按颜色单独渲染字母页。

## 9. 增量改一个词

1. 直接在台账里改，存盘关 Excel；
2. `xl_import.py` 回灌（先 `--dry` 看差异）；
3. `rebuild.py <lang> <color>` 只重建那一本；
4. 单本校验。

**不要直接改成品 .ai/PDF**：保存耗时占大头、不更快，还会破坏「决策 JSON 是唯一真相源」，下次重建把改动冲掉。

## 10. 明确不要做的三件事

- **不要在同一文档里连续翻译多语言**：① 替换靠「英文原文」当键，翻成第一种语言后键就变了，第二种语言的决策表键对不上，几乎翻不动；② 转曲不可逆，第一种语言的 PDF 一生成，文档就无法再用于第二种语言；③ 单双行行距、字号（从当前文本框读取）、位置（基于当前 top 再偏移）、baked 词（已转曲词是删图形后重建）都会逐次残留/漂移。必须每种语言从原稿重新打开。
- **不要直接改成品**：见第 9 节。
- **图文语义校验要谨慎投入**：插图在流程里只做几何避让（按真实墨迹 bbox），不做语义校验。若想用 VLM 校验「图 ↔ 原词是否匹配」，机器部分便宜但人工复核是主要成本，且大量抽象词/情绪/方位词无法用图校验；真正的译文对错要靠母语审校对照片，而不是看图。只值得做一次性审计，不值得做成常驻流程。

## 11. 常见故障

| 现象 | 原因 | 处置 |
|---|---|---|
| 保存失败「正被 Excel 打开」 | 台账还开着 | 关掉重跑 |
| `RPC 服务器不可用 0x800706BA` | 强杀过 Illustrator，COM 失效 | 清进程，重跑失败本；缺 PDF 的书必须补跑 |
| 只有 .ai 没有 .pdf | 崩在存 PDF 那步 | 整本重跑 |
| 跑了却什么都没生成 | 指纹判定未变 / 改了表没回灌 | 先回灌；确实要重做加 `--force` |
| 回灌 `changed` 上百条但没改过 | `\r`↔`\n` 未归一化 | 归一化换行符 |
| 批处理「看起来 FAIL」 | 只认某个计时日志，诊断脚本不打印 | 看日志里的实际完成标记，属误判 |

## 12. 实战问题全集（卡片量产三轮返工沉淀）

以下是真实大批量项目（4 配色 × 6 语言 = 24 本）从试做到量产踩过的每一个坑，按主题归类。做同类任务时逐条对照，能省掉整轮返工。

> **这些坑中可泛化的版式约束已落地为可执行代码**：`pipeline/make_jsx.py` 生成 JSX 时注入 `pipeline/geometry.jsx.inc` + `config.geometry`，自动实现 12.2 的红框规避、12.3 的双行行距、12.6 的标题椭圆适配与光学居中，并提供插图避让 guard（决策 JSON 的 `obstacles`）。`verify.py --layout` 做决策意图静态校验。12.1–12.8 保留为"为什么这样做"的原始经验；落地开关与坐标约定见 `pipeline/README.md` 的「版式约束」节。

### 12.1 Illustrator / ExtendScript 致命坑

- **JSX 里任何非 ASCII 字符（含中文注释）都会让 `DoJavaScriptFile` 报 "JavaScript code was missing"**：引擎按 ANSI 解析 UTF-8 无 BOM 文件。所有数据经驱动端 `js()` 转 `\uXXXX`，模板注释全用英文，生成后断言"无 >127 字符"。软回车用 `\r` 不要写 `\u000d`。（`pipeline/make_jsx.py` 已内置此断言。）
- **`.ps1` 必须存成 UTF-8 with BOM**：PowerShell 5.1 读无 BOM 的 UTF-8 中文脚本会解析崩、引号错乱。
- **`app.purge` / `PurgeTarget`**：Illustrator 28 根本没有这两个 API（`typeof` 为 undefined）。别指望 purge 缓解内存，加保护也行但别当真。
- **收尾 `close()` / `purge()` 在 `saveAs` 后抛 `PARM` 错但产物已保存**：把它们包进独立 try/catch 记 WARN，不要让批处理因为 `ERROR:` 误判重试——完成标记要在 try 块末尾、这些之后写入。
- **ExtendScript 没有 `JSON.stringify` / `Array.indexOf`**：写缓存用手工拼串；`inKeep` 这类查找手写循环。
- **日志路径必须绝对路径**：相对路径在 COM 上下文里解析到意外位置。
- **非目标画板要先裁掉再处理**：对象数 1.6 万→1 千，`processDoc` 从 279s 降到 13–48s。裁剪要在替换之前做。

### 12.2 转曲 / 保存 / 文件占用

- **转曲后出现红黑线框**：`unlockAll` 把源稿隐藏对象 `hidden=false / visible=true` 全显示了，带出裁切辅助标记。只解锁 `locked`，**绝不碰 hidden/visible**。
- **PDF 被 Acrobat/阅读器占用时 `saveAs(pdf)` 静默失败**：log 仍打印 SAVE_PDF、耗时几百 ms、mtime 不变。存 PDF 前先 `File.remove()` 旧文件；批处理启动前关掉 Acrobat/AcroRd32。
- **保存父目录不存在会弹「另存为」框阻塞脚本**：`saveAs` 前确保输出目录已建好。
- **PDF 兼容层必须保留**：`IllustratorSaveOptions.pdfCompatible=true`，否则 `.ai` 只能用 Illustrator 开，客户无法用 Acrobat 预览/置入排版软件。关掉省几秒、体积减半，但正常交付不得关。
- **强杀 Illustrator 后 COM 报 `0x800706BA`**：进程被强杀 → COM 失效。清进程后重跑失败本；中途别碰 Illustrator 窗口。对比：关文件后等待不足触发的是 `RPC_E_SERVERFAULT (0x80010105)`，两者不同。

### 12.3 文字替换 / 多行 / 断行

- **多行文本框（一个 frame 含 `\r` 两行，如 `subway station\r(underground station)`）**：PyMuPDF 按 span 拆行看不出来，整框精确匹配失败→漏译。用 `MULTILINE_KEYS` + 整框映射。
- **括号内容 = 美式/英式差异**：其他语言只有一种说法。以 `(` 开头的第二行只翻译主体、丢弃括号行；无括号的复合词（`swimming/pool`）才保留两行。
- **双行文本框是顶边锚定**：设 `contents` 含 `\r` 时顶边固定、向下扩展。双行易碰下方插图/超底框。行距也可用 `autoLeading=false; leading=字号×1.04`（更紧凑）；太小（0.92×字号≈16.6pt）字形高 20.8pt 会重叠，太大顶到插图。统一用 OS/2 typo 字形高 + 1pt 更稳。
- **德语/俄语复合单词断点**：`Bekleidungsgeschäft` 这种单 token 按空格拆不了。用 `DE_SPLIT` 之类字典给断点；单 token 默认禁止拆词。注意脚本里用真 `\n`，别写成 `\g`。
- **「放不下」的处理优先级**：横移 ≤8pt → 同排让位 → 短译法 → 双行（有空隙闸门才允许）→ 整列微移 ≤10pt → 待人工。不要一上来就缩字号（破坏字号对称）或平移到相邻词黏连（曾导致 `motocicletta/autobus` 黏在一起）。
- **可用宽度必须按"列距"算，不能按"标签墨迹间隙"算**：标签居中在插图下，两边都能长，但邻居同时在长。若只量 ink 空闲距离，独占一行的标签会算出 200pt（实测 365/635 个槽位顶到上限、中位 200），于是"超宽→折行"几乎永不触发，长译词直接压到邻列。正确口径是两标签的中心距 P，各自最多 `P-2×PAD`（P≈139.6 时约 119pt，与已验证工程一致）。
- **复合词 key（含 `\r`）查位置表要用首行**：`pos` 按单行文本索引，`"washing\rmachine"` 直接查不到 → `maxgap=0` → 永远进不了折行分支。
- **宽度表不得覆盖决策引擎已算好的折行**：决策 `val` 里已有 `\r` 时，若宽度表给的是未折行原文，不能回写（会把两行压回一行，实测 `camion dei pompieri` 变成 177pt 宽、撞到邻列）。只允许"宽度表折行而决策未折行"的方向覆盖。
- **折行后字号仍不得缩**：两行各行的宽度可能仍略超槽（如 5–8%），按本技能规则保留 18pt 并记 `BODY-OVERFLOW`，交给短译法解决，不得用缩字掩盖。
- **折行优先于短译，判据是"折完还留多少底边距"**：第二行会向下多吃一个行距（18pt 字号约 17.9pt）。只有 `标签下方空隙 ≥ 行距 + 8pt`（默认 `wrap_space_pt=26`）才折两行；不足时折行会把字顶到卡片边线（实测底部行只有 21–25pt 空隙，折完只剩 3–7pt），这时才用 `translations.json` 的 `"<lang>_short"` 短译法。短译不是首选，能安全折行的必须折行。
- **折行名额按"列"给，不按"整排"给**：同一排的不同列横向相隔一整列，各自折两行互不影响；按整排限 1 个会让本来有 130pt 空间的词被迫短译。
- **括号行（`(underground station)` 这类）不是独立标签**：它是上一行的同义第二行，不能参与折行名额竞争（会抢走自己第一行的名额，把 `subway station` 逼成短译），处理上由复合 key 继承第一行的结果。
- **正文长词要先有宽度表，否则长词直接冲出卡片**：`build_width_tables.py` 从源稿 spans + 译文 + 真实字体算出每个词的 `MAXW`（可用墨迹宽），并给出带 `\r` 的折行译文（`macchina\rdella polizia`）。表里**不缩字号**：放不下的词进 `overflow` 列表，由人换词。折行只允许在下方空隙 ≥ `wrap_space_pt`（默认 26pt）的槽位（可减去 `wrap_lift_pt` 的上移量），且同一列只折一个词，避免两行互相顶。
- **取字号别命中页码**：baked 词重排时若按颜色取样式，要过滤 `字号<16 或 >20` 且排除纯数字，否则命中白色 12pt 页码（字号对、颜色错）。

### 12.4 字形覆盖 / 字体

- **默认字体 `Arial Rounded MT Bold`**（PostScript 名 `ArialRoundedMTBold`，Windows `ARLRDBD.TTF`）。**西里尔语（俄）没有字形**，换 `Segoe UI Bold` / `SegoeUIBlack`（含西里尔、圆润粗体接近原版）。目标语言的特殊字符（œ é à ñ ü …）先做字形覆盖预检，缺则换字体并记入台账。
- **字母认知卡**：字母是手绘轮廓图形，翻译单词不会带动字母 → `Aa → яблоко` 错位。两条路线：①保留源稿英文 A–Z 与插图、只翻译单词，另出《字母对应表》说明（现行推荐）；②按 artboard bbox 找到字母组、读配色、删除后用目标字体重建大写+小写立体字（复杂，artboard 的 y 轴方向各画板不一致，bbox 换算不可靠，要把候选框画到页面上人工核对）。`Ww` 这类是两个独立字形组，要合并定位或分别删除。

### 12.5 台账 / 回灌 / 指纹

- **"译文==英文原文" 不一定是漏译**：同形词（panda/zebra/TV/SUV/jeans/pizza/hospital…）和借用词（俄语 SUV、巴葡 high five）本来就没变，先核实再改。
- **台账归类**：无映射对象应移到独立 sheet 标"未翻译-保留原文"，不要留在主表冒充已处理。文件被 WPS/Excel 占用时另存副本再替换。
- **出表覆盖前必须回灌**：否则用户在表里的编辑被静默丢弃。
- **指纹不含脚本、看产物 mtime 判成功**：详见第 5 节与 `pipeline/README.md`。

### 12.6 标题适配（第二轮返工教训：字号发散 / 压椭圆 / 两行不居中）

现象：同一个 `Numeri` 在第 6/7/8 页字号不同；`Colori` 只有 15pt；`Tempo atmosferico` 两行左对齐且压出椭圆；`Settimane` 左右各冒出椭圆 1.6pt。

根因与规则（按重要性）：

- **不要逐帧按椭圆重算字号**。早期 `fitTitle` 每帧独立求"最大可放字号"，必然给同一标题算出不同值（`Lettere` 23→21.62、`Weeks` 23→19.48）。正确做法：**一个标题一个字号，取自源稿该标题的实测字号**，同一 key 跨页复用；只在放不下时按同一条公式缩。该函数已从 `geometry.jsx.inc` 删除，现行实现是 `centerTitleInPill()`（先定位再按 `(x/a)²+(y/b)²` 缩，绝不放大）。
- **`var` 提升导致二次缩放**：折行分支里写 `var wr = wrapTitle(...)`，`var` 提升到函数级；一旦本书出现过一次折行，后续每个标题都命中 `if(wr)`，被多乘 0.94 并用**上一页的椭圆**再平移。证据：20.68=22×0.94、21.62=23×0.94、14.10=15×0.94，cy 也漂 0.7pt。**折行状态必须每帧重置**，别用裸 `var` 跨迭代传递。
- **标题胶囊是真椭圆**（源稿是 4 段三次贝塞尔，控制点系数 0.5523×半轴），不是圆角矩形。119.1×34pt 的椭圆：正中可用宽 119.1，升到字身半高（±8pt）只剩 **约 105pt**，两行标题第二行在 ±13pt 处只剩 **76.8pt**。所以判定要用 `(x/a)²+(y/b)²≤1`，不能用"宽度 ≤ 0.94×胶囊宽"糊过去；`Settimane` 22pt 宽 108.2 必然出头。
- **`ellipse_margin` 别设 0.94**：0.94 会把 105pt 的可用宽压到 96pt，导致过度收缩（`Settimane` 直接掉到 19.6）。默认 **1.0**，判定靠上面的椭圆方程本身。
- **段落对齐必须设在 `textRange` 上**：`tf.paragraphAttributes.justification = CENTER` 会被静默忽略，两行标题就左对齐（`Tempo` 中心 219 而 `atmosferico` 235）。要写 `tf.textRange.paragraphAttributes.justification`；枚举可用 `Justification.CENTER`，取不到时退回数值 2。
- **居中基准分两种**：单行按字身框（cap 顶→基线）居中，双行按墨迹框整体居中。用 `(top+bottom)/2` 会把带下伸字母的词（`Tempo`、`Stagioni`）整体顶高 2.4pt，跨页 cy 就不齐了。
- **单行判定允许下伸字母悬挂**：椭圆包含判定若把 `g/p` 的尾巴算进四角，`Stagioni` 会莫名比 `Numeri` 小 0.7pt。单行只按 `cap` 带（`top → top-cap×字号`）判定。
- **双行行距用 typo 行高**：`max(cap×字号+gap, 0.94×字号+1)`。`1.04×字号` 时代实测两行墨迹重叠 0.7pt（25.1–40.0 与 39.3–54.3）；低于 0.94em 下行必碰上行。
- **放不下才折行**：单行缩到源字号 85% 以下才折两行，折行字号用源稿双行标题的字号（如 `Colors`/`(Colours)` 的 15pt），再按椭圆收缩。
- **量宽度要在替换后 `app.redraw()` 再量**：直接量拿到的是原文几何，会误判"放得下"。
- **标题容器别用"标题+两侧装饰圆点"的联合 bbox**：比真椭圆宽约 20–24%。要扫描 `pathItems` 实测真椭圆，命中条件用"椭圆必须覆盖文字中心、取最贴合的那个"，别写反成"椭圆必须比文字窄"（那个条件会把标题自己的背景判掉，日志清一色 `TITLE no-ellipse`）。
- **日志里 key 含 `\r` 会截断整行**：`Colors\r(Colours)` 写日志时 `\r` 把该行前半段覆盖掉，看起来像"日志丢了数值"——其实是显示问题，不是逻辑异常。

### 12.7 稳定性 / 崩溃（最终结论）
- **崩溃根因是关文件后等待太短**：0.2s → 第 4 本崩；1s/3s → 全过；取 **2s** 为正式值。不是内存累积、不是重复打开已打开文件（诊断 `docs_before_open=0 / docs_after_close=0` 证明每本关干净）。单会话 24 本零崩溃。
- **不要按「每 N 本」分段重启**：等待充足后分段重启只是白付启动时间，一个会话跑完整批。
- **不要中途强杀进程**（见 12.2）。排障用 `V7_DIAG=1` 之类开关记录文档计数，默认关闭。

### 12.8 提速（不动正确性）

- **几何坐标缓存**（如标题椭圆位置）以源稿 size/mtime 为键：首次遍历上万路径几秒，之后读缓存降到 0ms，源稿一改自动失效。
- **未改动跳过（manifest 指纹）**：无改动时 `all` 模式 0 秒完成。
- **少做属性调用**：只解锁必要图层/文本框，不遍历两万个对象。
- **耗时大头是两次 `saveAs`（存 AI + 存 PDF），不是打开文档**：优化重点在保存环节。"同一文档连续翻译多语言省打开时间"收益极小且破坏正确性（见第 10 节），不要做。
| 单词用错字号/空白 | 取样式命中了页码等小号白字 | 加字号范围过滤与纯数字过滤 |

### 12.9 静默漏执行（第三轮返工：规则存在但没生效）

规则“写了但没执行”几乎都不是逻辑写错，而是**判据拿到空数据**或**产物被跳过**。三类真实案例：

- **几何导出漏标题行**：`geometry_export_template.jsx` 只把“1 个子项、尺寸在 `title_w/h_range` 内”的组识别成标题。某本 24 页里有 4 页标题画法不同 → 这 4 页没有 T 行 → `build_decisions` 生成不了 `title_map` 条目 → JSX 里 `TITLE[key]` 未命中 → 落到正文分支 → 决策里也没有 → **静默 `continue`，标题留英文，日志无一字**。现在 `export_geometry.py` 会按“画板数 vs T 行数”断言失败并指出缺哪几块画板；修法写进报错信息（`tune.titles` 或调门限）。
- **改规则后重建被 SKIP**：指纹不含 `width_tables.json` 时，改折行/短译再 `rebuild.py all` 会全部 `SKIP (unchanged)`，看起来像规则没生效。现已计入指纹。
- **JSX 两处静默 `continue`**：`if(!spec)continue`（正文查不到决策）和标题未命中，都没有日志。现在打 `KEY-NOTRANS` / `TITLE-MISS`（阈值 `layout.title_miss_size_pt`），结尾汇总 `REPLACED/TITLES/TITLE-MISS/KEY-NOTRANS`，非零再打一条 `WARNING`。

配套的“折行落位”规则（同一轮定稿）：

- **首行固定、向下生长**：折两行时第一行留在源稿单行位置，第二行向下扩展，和源稿自带的双行标签一致；不要居中骑跨（会同时向上顶到插画、向下压到卡片边）。
- **只在下边越界时整体上移**：`top0` 固定后若墨迹底越过画板底，按超出的量上移。**这条现已移到决策层**：`feasible_wrap()` 直接算出最小上移量 `dy`（只动文字）和 `illdy`（底排连插画），`make_jsx` 只执行，不再本地按"新增高度的一半"猜（两处各算一次会把文字抬两次）。

### 12.10 文本优先识别 + 转曲检测（第四轮：标题整页漏译）

**现象**：蓝色本 24 页里 4 页标题 `Behaviors` 永远是英文，日志一个字都没有。

**排查链路**：源稿那 4 页确实有活文本（`Behaviors`，21pt，胶囊 137.5×34）→ 但 `geom_blue.tsv` 里这 4 块画板**一条 T 行都没有** → 决策 `titles` 只有 20 条 → `title_map` 缺键 → JSX 命中不了 `TITLE[]` → 落到正文分支 → 决策里也没有 → `continue`。

**根因**：导出器只按"盒子尺寸"认标题（`title_w_range` 130–165 × `title_h_range` 28–40），这 4 页标题组的包围盒落在区间外，被归成了插图/其他。**按尺寸猜类型天生脆**。

**现在的规则（文本优先）**：

- **标题以"文字对象"为准**：组里若含标题级字号（`geometry_export.title_min_size_pt`，默认 19pt）的 `TextFrame`，就算盒子尺寸不合也判 T。正文 18pt 不会误判。
- **补一遍全文档文本扫描**：对象遍历只看顶层 `pageItems`，嵌套深的文本框会漏。现在扫描 `doc.textFrames`，凡没被已有文本行覆盖的，按字号补 T/L；去重只对 L/T/P 行做，**绝不对 F/I 行做**（卡片框会覆盖所有标签，用它去重会把要找的嵌套文本全吞掉）。
- **转曲检测**：标题带里有横幅状矢量（`outline_w_range`/`outline_h_range`）却没有任何活文本标题 → 输出 `X` 行（"标题疑似转曲"）；整块画板没有任何文本对象（L/T/P 全无）→ 输出 `Y` 行（"整页疑似转曲"）。
- **导出报错分级**：画板缺 T 但有 X → **只报告不失败**（文字已转曲，只能重导出或手工重绘）；缺 T 又无 X → 直接失败，报错里给 `tune.titles` 与门限两条修法。

**为什么值得**：`verify.py` 只查 PDF 存在/页数/是否全转曲，**不查英文残留**，所以这类漏译只能靠导出期与生成期的守卫暴露。

### 12.11 全新工程从零跑通（第五轮：换机重来的 6 个拦截）

把 `work/` 与 `output/` 全清空、只留译文表重跑意大利语一本时，整条链路在"以前能跑"的地方连续拦下 4 次。这些都是**只在干净环境才暴露**的：老工程里它们被历史文件掩盖了。

1. **非 ASCII 工程路径**（`G:/.../技能验证`）：`run_batch.ps1` 用 `Get-Content` 读 joblist，PS 5.1 默认按 ANSI 解码，UTF-8 的中文路径全变乱码 → 4 本全 `MISSING`，而画板/JSX 其实都正常。**读 joblist 必须 `-Encoding UTF8`**。
2. **joblist 必须是绝对路径**：runner 的 `$root` 是脚本所在目录（`<skill>/scripts`），相对项会在那里找 → 永远 MISSING。`rebuild.py` 与 `export_geometry.py` 都改成写绝对路径；`Join-Path $root <绝对路径>` 会拼成 `<scriptdir>\D://...`，runner 里要先用 `[IO.Path]::IsPathRooted()` 分流。
3. **JSX 日志命名契约**：runner 判定成功靠 `<脚本>.log`（**扩展名被替换**）。几何模板原来写在 `geom_x.tsv.log`、又写成 `<jsx>.jsx.log`，两种都对不上 → 每本判 "no log output" 重试两次，时间翻倍且汇总成 FAIL。**任何 JSX 都写 `ChangeExtension(自己,'.log')`**。
4. **`export_geometry.py all` 静默 0 本**：`args[1:]` 取到空表，打印 "geometry exported for 0 color(s)" 并 exit 0。语义已改为 `all = 全部配色`，且空选择不再算成功。
5. **标题带约束（新）**：只按"盒子尺寸 + 字号"认标题，日历页的月份格子（140×110、5 个子对象、含 19pt 文本）被误判成标题 → 月份缩写进了 `title_map`，页面上被当成标题塞进胶囊。实测真标题**无一例外落在卡片高度的 0.87 处**，误判的在 0.24 / 0.60 → 加 `geometry_export.title_band_ratio`（默认 0.25，即卡片顶部 25%），带外一律不判 T（组判定与全文档文本扫描都要加）。另加"同一画板多 T 行"告警。
6. **同一英文既是缩写又是全名**（`May` = 格内 12.8pt + 名下 18pt）：决策键是英文原文，一条记录装不下 `Mag.` 与 `maggio` 两个形态。**已实现按字号分身的机制**：最上面那一条（小字号）提升成独立键 `"<英文>#abbr"`，值取 `translations` 的 `"<lang>_abbr"`，记录里带 `szsrc`；`make_jsx` 生成时按文字框自身字号（±0.7pt）选键，另一个框用主译文。前置判据：同一串在同页**确实有两种字号且相差 ≥1.25 倍**，否则不动（`tree`/`rainbow` 这类正常重复词不受影响）。缺 `"<lang>_abbr"` 不猜，报 `ABBR-MISS` 让人补。
   - **缩写表要真的译成缩写**：德语月份曾译成全名（`Mar.→März`、`Jun.→Juni`、`Jul.→Juli`），会把小格子撑变形；法语 `janv./févr./juil./sept.` 是法语习惯写法，可保留。
   - **目标语言同形不算错**：意语 `Mar.` 同时是 marzo 与 martedì、法语 `mar.` 同时是 mars 与 mardi。两条词条的英文键不同（`Mar.` 与 `Tue.`），互不影响；**永远按英文键或页码区分，不要用译文反查**。

**耗时基线（单语 4 本、24/26/26/24 页）**：几何导出 60s（4 本各一遍）、决策+字宽+台账 <10s、出图 5m20s（28/103/86/81s）。任何一步出现"重试 2 次"或"0 color(s)"都说明上面 1–4 又回来了。

### 12.12 全新重建的三道守卫（第六轮：删掉 work 从零跑）

用户要求"删掉 outpu 台账 + work，从零再来"。静态核对时确认了三个**静默**失败点，都补成了硬拦截：

1. **译表覆盖不足 → 静默出全英文**：`tr()` 查不到就 `return en`，决策照样有 cx，JSX 把字替换成它自己，`verify.py` 只查页数与活字=0，**全绿**。现在 `build_decisions.py` 先算覆盖率：缺词条 >10% 直接 `REFUSED` 并列前 15 个；≤10% 只告警。同时把"译文与英文同形"的条目数列进报告（`mango/robot/jeans` 这类是正常的）。
2. **缺 `spans_all.json` → 所有标题变 22pt**：旧行为 `_book_single` 兜底 22.0，绿本 `Abbigliamento`(15.8)、橙本 `Body Parts`(14.7) 会被放大到撑椭圆。现在 `make_jsx.py` 缺文件即 `sys.exit(3)`（`SPANS-MISSING`），并把硬编码的 `spans_all.json` 改成 `cfg.f['spans']`。
3. **spans 没有生成器**：原来只有项目里的一次性 `extract_spans.py`，"换机从零"就断链。新增 `pipeline/export_spans.py`（配置驱动、写 `files.spans` + `unique_strings.json`、支持 `--color` 增量且不冲掉其它配色）。验证方式：与旧文件**逐条比对完全一致**（purple 219 / orange 201 / green 211 / blue 184 条）。

顺带修掉两个让"从零重跑"结果不可复现的小问题：
- `ledger_import.py` 对 `"#abbr"` 行用 `szsrc` 判定原稿字号，否则每次回灌都会给它写一个等于原稿的 `sz` 覆盖（决策文件凭每次多一个键）。
- `build_width_tables.py` 的 `overflow` 列表改为按英文排序：未排序时两次相同输入产出不同文件（集合迭代顺序），diff 全是噪声。

**复现性结论**：清空 `work/` + 台账后按 `export_spans → export_geometry → build_decisions → build_width_tables → ledger_export → rebuild → verify` 重跑，4 本决策与备份**逐条一致**（仅 `#abbr` 那条少了台账回灌产生的冗余 `sz`），成品页数/转曲/版式告警与上一轮完全相同。

### 12.13 语言表也能由技能生成（结构归脚本，内容归翻译）

**问题**：`translations.json` / `zh_gloss.json` 一直是手工拼的。键靠人眼从画稿抄，抄错一个字符不会报错——`tr()` 查不到就回落英文，`verify.py` 只查页数/活字，**成品照样全绿**。换一套卡片就得重抄一遍。

**分工**：技能没有翻译能力（无网络/无 LLM），但**结构与一致性完全可以归脚本**。新增 `pipeline/init_translations.py`：

- `--init`：键 = `spans` ∪ `geom` 的 L/T 文本。**必须并 geom**——两行复合词（`clothing\rstore`）在文本流里是两段，只存在于几何对象里。实测把旧表 626 键收敛到 623，并查出 **21 个死键**（`ear/eye/trousers/soup/sushi/swimming pool…` 源稿里没有）。
- `--keys`：输出 `tr_keys.txt`，供分批翻译（本次 623 键分 3 批，`unknown=0`）。
- `--merge`：幂等；未知键**拒绝并计数**；支持 `{"en":{"it":"..","zh":".."}}` 一文件同时回填译文与中文。
- `--check`：缺键/多键/空值率/两行复合键数/`_short`/`_abbr` 数/中文覆盖，`--strict` 时有问题退出码 3。

**实测收益**：中文对照从 615/626（缺 84）→ **623/623**；脏 override（`purple|15|may（缩写格）`）随重生成消失；意语译文 43 条措辞与旧表不同（多为修正：`high five` 由 `cinque alto`→`batti cinque`、`back` 由 `indietro`→`schiena`、`short` 由 `corto`→`basso`、`Weather` 由 `Tempo atmosferico`→`Meteo`），决策布局（cx/dy/sz）**零变化**——说明版面由几何决定，换措辞不动版。

**内容仍然要人**：这 623 条意语是 agent 现场写的；换语种/换批次要么 agent 写，要么接翻译 API。`--check` 的覆盖率与 `build_decisions` 的 `TRANS-MISSING` 守卫是两道闸，缺内容会被拦，不会静默出英文。

### 12.14 折行落位的优先级（第七轮：先文本上移，插画只在底排且最后考虑）

**问题**：`cadeira de rodas` 被短译成 `cadeira`。查下来不是 JSX 不折，是**字宽表在源头否决折行**：折行门槛 `wrap_space_pt=26` 是按"文字单独向下长"定的，而底排标签底到卡底只有 22.5pt（扣 6pt 边距可用 16.5）→ 判"没空间"。

**两个口径冲突**（记下来，别再混）：

- **决策层（`build_decisions.py`）** 判"卡边"：`try_single()` 在 `shift_cap_pt`(8pt) 内平移 `cx`，`violations()` 查**卡片内框** `fx0/fx1/fyb/fyt` + 与邻居间距 `inter_label_gap_pt`(10.5)。实测 `cadeira de rodas` 148.2pt 宽、右端 1283.7、卡右界 1308.4 → **卡内合法**。
- **字宽表（`build_width_tables.py`）** 判"列槽"：槽宽 = 同排相邻标签中心距 − 2×PAD = 114.3pt，比卡边严得多，且拿不到卡片边界 → 它才是判折行/短译的地方。

**落位优先级（现行）**：

1. **内移**（决策层，±`shift_cap_pt`）——不动字号、不折行能放下就结束；
2. **大内移**（决策层，±`relax_shift_pt`，仍限本列）；
3. **折行**（决策层 `feasible_wrap` 证明放得下，字宽表只负责给出平衡的两行文本）——折行块向下长，只有越卡底时才上移：先只动文字（`dy`，上限 = 文字净空 `room`）；`room` 不够且该标签在**底排**（`illok=1`：标签底距卡底 < `bottom_row_pt`(60)）时，才把自己的插画一起上移（`illdy`，上限 = 该排所有插画上方净空 `ceil` 的最小值）；同排其它格只跟随文字（`rowdy`），插图不动；
4. **短译**——以上都不行才用 `<lang>_short`；
5. 兜底 `manual` / `PN-TIGHT`：交人工换词，绝不把文字顶进插画、绝不缩字号。

> 上移由**决策层**算进 `dy`/`illdy`/`rowdy`，`make_jsx` 只执行、不再本地重算（旧版两处各算一次，文字被抬了两次）。日志里不会再出现 `WRAP-UP`，改看决策 JSON 的 `dy`/`illdy`。

**静态实测（6 语 × 4 本，双行条目 177 条）**：`no-lift` 124（折行后仍在底边距内）、`text-only` 39（如 `up` room 15.7、`rocking horse` 10.6、`hot air balloon` 6.8、`wheelchair` 3.4，want 均 1–3pt）、`text+art` 14（全部 `illok=1` 且同卡无更低标签）、`WRAP-TIGHT` 0。

**踩坑**：`room` 初版写成"标签顶 − 插画底"，在 Y 轴向上的坐标系里正好反号 → 全部算成 0，于是所有条目都走"插画上移"。判据统一按 `插画底 − 标签顶`（正值 = 有净空）。

**插画定位实现**：决策里带 `ill` 框，JSX 一次性建 `pageItems` 索引（按框差匹配，容差 8），逐条扫描会慢到分钟级（20k 对象）；移动后同步平移 `OBS` 里对应矩形，否则碰撞守卫会拿旧框误报。

### 12.15 版式事实契约化 + 整排同步上移（第八轮）

**问题**：折行落位的判据散落在决策层里现算（`own_illus` / `room` / `ceil` / 底排），同一套几何被两处用不同符号解释过，`room` 就曾因 Y 方向写反全部算成 0。换一套版型时这些"现算"要么静默为 0，要么算错，都不报错。

**改法（三层）**：

1. **事实下沉到 `geomlib._attach_facts()`**：每页每标签一次性算出 `row`（行号）、`ill`（自身插画框）、`room`（文字可上移净空 = 插画底 − 文字顶 − `obstacle_gap_pt`）、`illok`（是否底排）、`ceil`（插画上方净空，剔除本排对象）。决策层只读字段，不再自己扫对象。无插画的标签（色块、裸形状、日历格）改测"标签上方的净空"，不再一律 0。
2. **缺事实硬失败**：`build_decisions.py` 开头统计两类缺口 —— 有标签却没有内框的页 → 直接 `REFUSED`（原来 `continue`，该页保持英文且日志干净）；无插画标签占比 > `layout.facts_max_missing_ratio`(0.5) → `REFUSED`，35%–50% 提示。报错文本直接指明该看哪个参数（`geometry_export.illus_above` / `own_illus_cy_gap` / `files.geom_inner`）。
3. **`preflight.py`（新增）**：出决策前打印每色的页数/标签数/底排数/行数分布、每语言译表覆盖与 `_short` 数、上次决策的模式统计与未解条目；有阻断项退 2。

**整排同步上移（用户选的方案）**：一条底排标签折两行、文字净空不够时，**不再单独抬高它自己的插画**——那会让同一排三张图高低不一。改为按行整体上移：`feasible_wrap()` 返回 `(cx, dy, illdy, rowlift, mates)`，`rowlift` 同时加到该行每个成员的 `dy` 与 `illdy` 上；`rowlift` 的上限是该行所有插画上方净空的最小值。台账"模式"列标为 `keep·整排↑23.5` / `wrap·整排↑23.5`，审校一眼能看出这一排为什么比英文原稿高。

**踩到的坑**：

- **对齐遍把上移抹掉**：`for _ry, mem in rows` 的"整排对齐"会重算整排 `dy`，把折行的 `dy` 和 `rowdy` 一起覆盖（实测三格文字比插画高 23pt）。现在含 `wrap` 或 `rowdy` 的行跳过对齐——折行已经把位置定死，上移本身是等量的，不需要再对齐。
- **JSX 二次抬升**：`make_jsx` 里还有一段本地 `wrapDy` 兜底，会与决策层的 `dy` 叠加。已加 `if(!spec && ...)`：决策层说过话就完全听它的，本地只在没有决策时才猜。
- **回退顺序**：`内移(±8) → 大内移(±26, 仍在本列内) → 折行 → 短译`。原先 `大内移` 排在短译之后，导致 `cadeira de rodas` 只差 1.8pt 时被换成错误的短词 `cadeira`（=椅子）。

**这一轮的结果（6 语 × 4 本）**：`wrap` 66→37、`short` 9→14、`manual` 25→28；整排上移 5 组（意/俄绿本 p14 三格 23.5pt、俄绿本 p19 10pt、巴葡紫本 p21 11.9pt），同组 `illdy` 完全一致。

### 12.16 "修不动就静默出图"清零（第九轮：长文本压插画）

**问题**：决策层修 10 轮后放弃的标签**不留任何痕迹**照原样出图——`mode=manual` 只是台账里一个词，PDF 照样把 164pt 的单行画出卡边、压进插画。终态审计（把 `violations()` 的结果记回 state 再打印）暴露 32 条：中排标签 `illok=0` 永远不能折行、日历全名 Monday–Thursday 没有短译、row 打包后仍 TX。

**改法**：

1. **`layout.wrap_clear_pt`（默认 1.0）**：折行块与下方障碍的净空从 2mm 降到 1pt。2mm 是"一般障碍"的 cushion，但源稿设计本身只留 1–2pt——不降的话 `ice skating / police car / high jump` 差 3–6pt 被否决。同时 `violations()` 里 IL/PN 的下限也从 `min(MM, sep_orig)` 改成 `min(wrap_clear_pt, sep_orig)`（标签间距 TX 仍按 IGH，不受影响）。
2. **补齐 34 条 `<lang>_short`**：日历星期用目标语言官方缩写（de `Mo./Di./Mi./Do.`、pt `seg./ter./qua./qui.`、ru `Пн./Вт./Ср./Чт.`——源稿本来就配了 `Mon.`/`Monday` 缩写对），德语复合词 `Modehaus`/`Süßwaren`，俄语 `полиция` 等。manual 12→**0**。
3. **mode=wrap 必须带 `\r` 的硬校验**：两次出现 `mode=wrap` 的值丢了换行符（164pt 单行出图），原因未定位——现在写回时自愈（`wrap2` 重建并记 `WRAP-VAL-RESTORED`），写完文件后回读校验，不一致直接 `REFUSED`。
4. **复合键的坑**：`{"clothing\rstore": ...}` 写进 JSON 时 `\r` 是字面反斜杠+r，不是回车——merge 报 `unknown=1`，要用真 `
`。

**结果**：违规标签 32 → **4**（只剩 ru 紫本两个颜色词 `фиолетовый/коричневый` 比邻居近，row 打包后的 TX；俄语颜色词没有标准缩写，待人工定）。意语 4 本全绿：`pattinaggio/su ghiaccio`、`macchina/della polizia` 折行成功，`seg./ter.` 等进日历格。
